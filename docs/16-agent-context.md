# 16. Контекст для AI-агента

> **Цель:** любой агент может прочитать этот файл и сразу продолжить работу,
> не переспрашивая базовых фактов. Дополняет `00-resheniya.md` и `13-karta-pamyati-th4.md`.

## Проект в одном абзаце

Играть в **Diablo 1: The Hell 4 (TH4)** в **3D внутри Garry's Mod (GMod)**.
TH4 — авторитет по игровой логике (pathfinding, бой, подбор), GMod — 3D-представление
(рендер + управление). Связь — мост (Python reader памяти + Lua-аддон).

## Текущий статус (на 20.10.2026, вечер)

### Цель проекта (переформулирована 20.10.2026)

**«Поиграть в Diablo в 3D»** — причём интересно «пострелять» как в
Heretic/Hexen, но на **хардкоре** и на **рандомных уровнях Diablo**.
TH4 при этом остаётся источником правды (её ИИ/лут/магия/генерация уровней
используются как есть), GMod — 3D-представление + пульт.
План по шагам: **`docs/19-plan-3d-shooter.md`**.

### Что работает

1. **TH4 → GMod (чтение состояния) — напрямую через shared memory:**
   - `th43d.exe` публикует состояние в именованную разделяемую память `D1BridgeState`
   - `garrysmod/lua/bin/gmcl_d1bridge_win64.dll` (Lua-модуль GMod) читает её
   - `d1bridge.lua` (аддон) рисует HUD
   - **Никаких файлов, никакого Python-моста**
   - **Серверный модуль `sv_d1bridge_win64.dll` тоже установлен** → сервер
     читает SHM напрямую (нужно для шага 2 плана: двигать игрока в клетку героя)

2. **GMod → TH4 (управление) — работает:**
   - `send_command` в DLL → команда в shared memory → `Player.walkPath` в TH4
   - Механизм: `ClearPlayerPath()` + `MakePlayerPath(row, col, 1)` —
     ровно то, что TH4 делает при клике по клетке
   - Движение: `PCMD_1_WALKUR` … `PCMD_8_WALKL` (1..8)
   - **Проверено в игре:** герой ходит, все 8 направлений верны,
     задержка **ввода 54–110 мс** (клик-фолбэк был 209–454 мс)
   - Работает и в городе, и в подземельях
   - **Важно: GMod — мир Z-up!** Горизонталь = XY, читать `f.x`/`f.y`, НЕ `f.z`

3. **MVP-спайк закрыт полностью** (все 6 критериев, см. `10-mvp-spike.md`)

4. **3D-сцена уровня — код написан и рисуется (IMesh), не отлажен визуально:**
   - `bridge/gmod/d1scene.lua` — уровень из настоящих данных TH4
     (`FineMap`/`TileBlockWalking`), 3300+ квадов, ~1.7 мс на кадр
   - камера через `cam.Start3D` (единственный рабочий способ в этой сборке)
   - режимы `player` (от первого лица) / `iso` (изометрия TH4)
   - **не проверено глазами**, что сцена на экране выглядит как надо

### ⚠️ Главное, что надо знать про GMod в этой сборке

Полные таблицы — **`docs/17-gmod-api-ogranicheniya.md`**. Коротко:

* `mesh` — immediate-mode **IMesh**: `Begin(type 0..7, count, [material])`,
  `Quad(v1..v4)`, `End`. `mesh.Start` **не существует**.
* `surface.DrawPoly` **не рисует**. `DrawRect`/`DrawTexturedRect*` — работают.
* `render` без `OverrideViewOrigin/Angles`; `CalcView` вызывается, но его
  значения **игнорируются**.
* Хуки: работают `Think`, `RenderScene`, `DrawOverlay`, `PreRender`…;
  **не работают** `PreDraw`, `PostDraw`, `HUDPaint`.
* `ply:SetEyeAngles()` **не применим** (сервер владеет игроком).

### Как выглядит 3D-сцена сейчас (состояние на 20.10.2026 вечер)

* `d1scene.lua` рисует уровень через IMesh в хуке `RenderScene`.
* Камера — `cam.Start3D` с ракурсом из `D1Control` (база TH4: 225°/30°).
* Режимы: `player` (уровень вокруг игрока, камера штатная — вид от первого
  лица) и `iso` (своя камера, изометрия TH4).
* **Проблема:** пользователь всё ещё видит вид «сверху» — значит режим
  `player` либо не применился, либо уровень рисуется не там. Это первое,
  что надо проверить в следующей сессии (`d1scene_info` → строка
  `режим=… камера=…`).
* Отдельно: `d1iso.lua` (2D-изометрия) — запасной путь; его текстура-атлас
  (TGA/PNG, генерируется в runtime) **не загрузился** — см. «Открыто» в
  `docs/00-resheniya.md`.

## критические правила (из журнала решений)

1. **Раскладка Player в запущенной сборке отличается от клона** (префикс +4, хвост −1).
   Всегда использовать эмпирические смещения из `offsets.json`, не из исходников.

2. **Имя героя в структуре лежит ДВАЖДЫ** (по `+0xA8` и `+0xA8 + 0x174`).
   После нахождения кандидата по имени обязательно проверять поля (Row/Col/HP).

3. **Окно TH4 нельзя сворачивать** — только перекрыть GMod или убрать на второй монитор.

4. **Клик в окно TH4 требует серии WM_MOUSEMOVE** (3 × 30 мс) перед кликом,
   иначе игра обрабатывает клик по предыдущей позиции.

5. **Дедуп команд по `SysTime()` + `sid`** (не по `seq`/`os.time()`).

6. **HP/мана — fixed-point (×64).** `CurLife=3200` при реальном значении 50.

7. **`e:\games\The Hell IV\` не трогать** (замена exe ломает сейвы/язык).
   Вся экспериментальная сборка — только в `e:\games\TheHell3D\`.

8. **Адреса структур из `d1map_export.txt` нестабильны** — читать файл свежий
   после каждого запуска `th43d.exe`, не хардкодить.

## Структуры данных TH4 (из исходников)

```
FineMap[112][112]      — int, индекс тайла (0..2048) для каждой клетки
PlayerMap[112][112]    — char, кто стоит в клетке (0 = никого)
TileBlockWalking[2049] — uchar, 0 = можно ходить, ненулевое = стена
TileMap[112*112]       — TileColumn, рендер-тайлы (пока не используется)
```

Адреса из `dataseg.cpp` (для клона, **не для запущенной сборки**):
- `FineMap` — `0x005F5BB0`
- `TileBlockWalking` — `0x0060B2E0`

**Текущий способ получения адресов:** собрать `th43d.exe` и прочитать
`d1map_export.txt` (см. «Сессия 19.10.2026»). Сканирование памяти — фолбэк/тупик.

## Сессия 20.10.2026 (вечер) — 3D-сцена, API GMod и смена цели

### Что сделано

1. **Точная геометрия изометрии TH4** (расчётом, проверено на 8 направлениях):
   мир `X = Col·k`, `Y = Row·k` (Z-up), камера `yaw=225°`, `pitch=+30°`
   даёт проекцию **ровно** TH4 (`px=(dRow−dCol)·64`, `py=(dRow+dCol)·32`).
   → `docs/18-geometriya-izometrii-th4.md`.

2. **Разобрана сборка GMod этого пользователя** — куча «дыр» в клиентском API:
   `mesh` оказался immediate-mode IMesh, `surface.DrawPoly` не рисует,
   `render.OverrideView*` отсутствуют, `CalcView` игнорируется, `HUDPaint`
   молчит. Работают: `RenderScene`, `DrawOverlay`, `cam.Start3D`.
   → `docs/17-gmod-api-ogranicheniya.md` + 7 зондов в `bridge/gmod/`.

3. **3D-сцена переписана на IMesh** (`d1scene.lua`): настоящие данные TH4,
   ~3300 квадов, ~1.7 мс на кадр, камера через `cam.Start3D`, два режима
   (`player` — от первого лица, `iso` — изометрия TH4).

4. **Клиентский модуль продублирован как серверный**: `sv_d1bridge_win64.dll`
   установлен → сервер читает SHM напрямую.

5. **Цель переформулирована**: «поиграть в Diablo в 3D», стрельба как в
   Heretic/Hexen, на хардкоре и рандомных уровнях. TH4 остаётся источником
   правды; порт механики отклонён (Р-39). → `docs/19-plan-3d-shooter.md`.

### Проблемы

* Режим `player` (вид от первого лица) не дал нужного вида — пользователь
  всё ещё видит «сверху». Не разобрано (следующий приоритет).
* Текстура-атлас для 2D-изометрии, записанная в runtime, не подхватилась
  материальной системой (`Material()` → ошибка).
