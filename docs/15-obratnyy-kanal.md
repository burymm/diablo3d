# 15. Обратный канал: GMod → TH4 (клик-фолбэк)

Дата: 16.10.2026. Закрывает пункты №5–6 критерия MVP-спайка (`10-mvp-spike.md`):
**«клик в точку перед героем → герой идёт»** и **«оценка задержки»**.

## Схема

```
GMod (Lua)                     файловая очередь                  reader (Python)
-----------                    ------------------                 ---------------
d1_step right  ──►  data/d1bridge/bridge_cmd.json  ──►  опрос 20 мс  ──►  ввод в TH4
                                            ◄── snapshot.json (+ack)  ◄──  чтение состояния
```

Команда и ответ идут **разными файлами**: `bridge_cmd.json` пишет GMod,
`snapshot.json` пишет reader (в нём же «липнет» `ack` последней команды).

Ввод доставляется **эмуляцией мыши**, без записи в память TH4 (Р-8): игра сама
решает, что делать (pathfinding, атака, подбор).

## Главное: как на самом деле работает ввод в TH4

Всё ниже получено экспериментально и держится на трёх правилах.

### 1. Позицию клика игра берёт из НАСТОЯЩЕГО системного курсора

`PostMessage(WM_LBUTTONDOWN)` с координатами в `lParam` **игнорируется**.
Проверка: настоящий курсор уводили в (300, 1000) и просили «вправо» — герой
шёл туда, куда указывал курсор, а не куда просили. Без `SetCursorPos` не
работает **ничего** (проверено 8/8 «стена»).

### 2. Перед кликом нужна СЕРИЯ `WM_MOUSEMOVE`, разнесённая по кадрам

Одно сообщение движения перед кликом недостаточно: игра обновляет свой курсор
по кадрам. Наблюдался характерный симптом — **сдвиг ровно на одну команду
назад**: просили «вправо» → герой делал шаг, который был заказан *до этого*.
Рабочий рецепт: `SetCursorPos` → 3 × (`WM_MOUSEMOVE` + пауза 30 мс) →
`WM_LBUTTONDOWN` → `WM_LBUTTONUP` → пауза 100 мс → вернуть курсор.

Константы: `MOUSE_MOVES`, `MOUSE_MOVE_GAP`, `CLICK_DWELL` в `thclick.py`.

### 3. Окно TH4 должно быть РАЗВЁРНУТЫМ; фокус ему НЕ нужен

| Состояние окна TH4 | Результат |
|---|---|
| **развёрнуто, но не в фокусе** (перекрыто GMod / на втором мониторе) | **работает, 8 из 8** ✅ |
| развёрнуто и в фокусе | работает (режим настоящей кнопки), но фокус забирается |
| **свёрнуто** | **не работает вообще** ❌ — игра ввод не обрабатывает |

> Первая версия документации утверждала, что свёрнутое окно работает. Это было
> ошибкой эксперимента: курсор в тот момент случайно лежал на проходимой
> клетке, и «движение» происходило не туда. Проверка с намеренно уведённым в
> сторону курсором опровергла это однозначно.

**Итоговая схема для игры:** TH4 — развёрнутое окно без фокуса (можно
перекрыть GMod), GMod на весь экран и с фокусом. Курсор пользователя на
время команды уводится и возвращается обратно.

### Ловушка: у свёрнутого окна `GetClientRect` = 0×0

Наивный перевод координат сломался бы (деление на ноль). `thclick.client_size()`
берёт `GetClientRect`, а при нуле — `GetWindowPlacement(rcNormalPosition)` плюс
`AdjustWindowRectEx`; `client_origin()` считает оттуда же положение клиентской
области на экране.

### Баг первой версии, который стоил двух часов отладки

`SetForegroundWindow` вызывался без проверки и без `AttachThreadInput`.
Windows молча отказывал, окно TH4 оставалось на заднем плане, а клик уходил
**по абсолютным экранным координатам в другое приложение** — reader радостно
отвечал `click OK`, герой не двигался.

Правило: любой синтетический ввод по абсолютным координатам обязан проверить
foreground перед кликом и **отказаться** кликать, если окно не активно.

## Геометрия экрана TH4 (измерена)

Первая версия считала, что тайл 64×32 и герой в центре окна. Неверно, и поймано
сравнением «куда просили» и «куда герой пришёл». Рабочая модель:

```
px = cx + (dRow - dCol) · 64      ← TILE_W = 128, TILE_H = 64
py = cy - 64 + (dRow + dCol) · 32 ← ANCHOR_DY = -64
```

`(cx, cy)` — центр клиентской области (при 2560×1440 это `1280, 720`).

1. **Герой нарисован НЕ в центре окна, а на 64 px выше.** Клик «в центр окна»
   попадает в клетку `(Row+1, Col+1)`, а не в героя.
2. **Таблица направлений** своя, отличается от «школьной» изометрии:

| направление | dRow, dCol | клик (px) | направление | dRow, dCol | клик (px) |
|---|---|---|---|---|---|
| up | −1, −1 | (1280, 592) | down | +1, +1 | (1280, 720) |
| up-right | 0, −1 | (1344, 624) | down-left | 0, +1 | (1216, 688) |
| right | +1, −1 | (1408, 656) | left | −1, +1 | (1152, 656) |
| down-right | +1, 0 | (1344, 688) | up-left | −1, 0 | (1216, 624) |

3. **Клик делаем точно в центр клетки.** На границе между клетками игра выбирает
   соседа иначе: свип по сетке давал для граничной точки то `(+1, 0)`, то
   `(+1, −1)`. Центры однозначны — поэтому `step`/`goto` бьют в них.

Проверка 8 из 8 (окно не в фокусе, курсор уведён в сторону):

```
направление |      клик px |    ждали |     факт | вердикт
          up | ( 1280,  592) | (-1, -1) | (-1, -1) | OK
    up-right | ( 1344,  624) |  (0, -1) |  (0, -1) | OK
       right | ( 1408,  656) |  (1, -1) |  (1, -1) | OK
 down-right | ( 1344,  688) |  (1,  0) |  (1,  0) | OK
         down | ( 1280,  720) |  (1,  1) |  (1,  1) | OK
  down-left | ( 1216,  688) |  (0,  1) |  (0,  1) | OK
        left | ( 1152,  656) | (-1,  1) | (-1,  1) | OK
    up-left | ( 1216,  624) | (-1,  0) | (-1,  0) | OK
верно 8, неверно 0, стена 0
```

> Константы: `SCREEN_GEOM`, `STEP_DIRS`, `STEP_ALIASES` в `d1reader.py`.
> При другом разрешении окна их надо переизмерить той же методикой.

## Формат команды

```json
{"action":"step","dir":"right","n":1,"real":false,"seq":1,"ts":12345.678,"sid":"..."}
```

| Поле | Смысл |
|---|---|
| `action` | `ping` (связь), `click` (точка окна), `step` / `goto` (клетки) |
| `x`, `y` | нормализованные координаты клиентской области, `0..1` (только `click`) |
| `real` | `false` — курсор+PostMessage (по умолчанию), `true` — настоящая кнопка |
| `dir` | `up up-right right down-right down down-left left up-left`, синонимы `w a s d q e z c` |
| `row`, `col` | целевая клетка для `goto` (абсолютные) |
| `drow`, `dcol` | сдвиг клетки для `step` (если не `dir`) |
| `n` | на сколько клеток идти (по умолчанию 1) |
| `seq` | счётчик для человека (сбрасывается при рестарте GMod) |
| `ts` | `SysTime()` GMod — по нему дедуп (нужна субсекундная точность) |
| `sid` | идентификатор сессии GMod; смена = рестарт, дедуп сбрасывается |

**Геометрию экрана знает только reader** — у него есть позиция героя и размер
окна. GMod думает в клетках, а не в пикселях.

Ответ (`ack` в `snapshot.json` + `ack_ts`, `ack_rx_ts`):

```
step OK: (45,86) -> (44, 86) [-1,+0] PostMessage+курсор at 1216,624 screen (1216,624) (client 2560x1440, окно НЕ в фокусе) seq=1
goto OK: (66,80) -> (68, 80) [+2,+0] PostMessage+курсор at 1408,720 ...
step FAILED: неизвестное направление 'banana' (доступно: up, ..., up-left) seq=1
```

## Команды в игре (GMod)

| Команда | Действие |
|---|---|
| удержание `W A S D Q E Z C` | идти, пока клавиша зажата (кликает reader) |
| `d1_step right` | шаг на клетку в сторону |
| `d1_step w 3` | шаг на 3 клетки |
| `d1_goto 50 87` | идти в клетку `Row`/`Col` |
| `d1_hold [0\|1\|len N]` | вкл/выкл удержание, длина шага (по умолчанию 3 клетки) |
| `d1_mode post` / `d1_mode cursor` | способ ввода (по умолчанию `post`) |
| `d1_click [x y]` | клик в точку окна (0..1), низкий уровень |
| `d1_ping` / `d1_ack` | проверка связи / ответ reader'а |

## Замер задержки (16.10.2026)

| Этап | Задержка |
|---|---|
| запись команды → подхват reader'ом | **5–30 мс** (медиана 15) |
| служебные паузы ввода (3 × 30 мс + 100 мс) | ~190 мс |
| **команда → герой сдвинулся** | **209–454 мс, медиана 428** |
| снимок | 10 Гц (`--interval 0.1`) |

По направлениям (режим настоящей кнопки, для сравнения): клик **ниже ног
героя** — 110–270 мс, на уровне ног и выше — 400–430 мс. Воспроизводится;
внутри TH4, вероятно разворот/анимация.

**Удержание клавиши (после переделки):** GMod шлёт `hold` один раз при нажатии,
reader кликает сам — только когда герой стоит. Итог: **0.9 клика/с и 1.8 скачка
курсора/с** против 2.2 и 4.4 у прежнего потока команд, при этом скорость выше:
**2.7 кл/с** в подземелье (было 1.87). Если путь перекрыт, клики прекращаются и
в `ack` приходит `путь перекрыт` — курсор не дёргается вхолостую.

**Вывод по ощущениям:** 0.2–0.45 с — уровень «классической стратегии», но **не
FPS**. Для управления от первого лица понадобится предсказание на стороне GMod
или команды внутри TH4 (`destAction`) — см. `11-upravlenie-i-kamera.md`.

## Ограничения (осознанно)

- **Окно TH4 нельзя сворачивать** — только перекрыть или убрать на второй монитор.
- **Системный курсор дёргается** на ~0.3 с на команду (потом возвращается).
- **Дискретное управление**: только «шаг на N клеток», скорость задаёт игра.
- **Стены**: длинный клик упрётся в преграду — герой дойдёт до неё.
- **Клик по границе клеток** неоднозначен — бьём в центр.
- **Курсор TH4** не читается: `CursorRow`/`CursorCol` (смещения `0x123`/`0x125`)
  — не координаты курсора (наблюдались `0,0` и `0,-1`). И не нужно.
