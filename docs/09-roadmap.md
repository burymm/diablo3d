# 09. Дорожная карта (черновик)

Порядок вех выбран так, чтобы как можно раньше получить **сквозной результат** («данные из
TH4 видны в 3D»), а качество и универсальность наращивать позже.

## Фаза 0. Прототип чтения памяти (MVP, выбранный путь)

См. подробно `10-mvp-spike.md`. Цель — доказать, что мы вообще можем достать из памяти TH4
реальные меняющиеся данные и отдать их в GMod.

- [ ] Простейший reader: находит процесс `TH4.exe`, читает память.
- [ ] Найти якорь (имя героя → `struct Player`), читать `CurLife/CurMana/CharLevel/Row/Col`.
- [ ] Писать `snapshot.json` в `garrysmod/data/d1bridge/`.
- [ ] GMod-прототип читает файл и показывает значения.
- [ ] Оценить задержку/частоту чтения, устойчивость поиска на разных сборках `TH4.exe`.

**Выход:** работает сквозной поток «TH4 → reader → файл → GMod».

## Фаза 0.5. Спайки (параллельно/после)

- [ ] S1: собрать `vendor/the-hell-4-src` (MSBuild, Win32, `fxc.exe`), запустить, убедиться,
      что играется наша установка (разблокирует Вариант A).
- [ ] Изучить `src/Server.cpp` / `Server/Server.vNext.vcxproj` — есть ли headless-режим.
- [ ] Изучить точную формулу изометрии (`Draw.cpp`, `Engine.cpp`) и структуру `TileMap`.

**Выход:** понятно, переходим ли к варианту A (исходники).

## Фаза 1. Экспорт состояния (read-only)

- [ ] В TH4 (или внешним reader’ом) сформировать **снимок мира**: dlvl, `PlayerMap`/`TileMap`
      (упрощённо), игрок, монстры, объекты, предметы, снаряды.
- [ ] Отдавать его во внешний мир простейшим транспортом (файл-JSON в общую папку).
- [ ] Проверить стабильность и частоту.

**Выход:** поток данных о мире, пригодный для потребителя.

## Фаза 2. GMod-вьюер (L1: наблюдение, без управления)

- [ ] GMod-аддон читает снимок (`file.Read` из `garrysmod/data/d1bridge/`).
- [ ] Строит 3D-сцену уровня: пол/стены (билборды, вариант A).
- [ ] Отображает героя/монстров/предметы как билборды с направлением и анимацией.
- [ ] Камера: сверху/третье лицо; плавная интерполяция.

**Выход:** можно «полетать» над уровнем Diablo в 3D, наблюдая за игрой.

## Фаза 3. Управление (L2)

- [ ] Обратный канал команд: `move_to`, `attack`, `cast`, `use_object`, `pickup`.
- [ ] Ввод в GMod (курсор/луч → `(row,col)`/id) → команда в TH4.
- [ ] Проверка соответствия: персонаж реально действует в TH4.

**Выход:** играемо из 3D-вида.

## Фаза 4. UX (L3)

- [ ] HUD (жизни/мана/опыт/панель скиллов) в GMod.
- [ ] Инвентарь/экипировка/персонаж (derma/VGUI), события/звук/эффекты.
- [ ] Оптимизация рендера (батчинг, отсечение), режим «один экран» (headless).

**Выход:** комфортная 3D-игра.

## Фаза 5. Универсальный API (L4)

- [ ] Зафиксировать `d1api` (схема + версия + документация).
- [ ] Транспорт прод-уровня (pipe/TCP + бинарный/MessagePack; опц. HTTP/WebSocket).
- [ ] Второй потребитель (например, веб-вьюер или мини-клиент) — доказательство
      универсальности.
- [ ] SDK для GMod (`gmcl_`-модуль) и, при желании, для C#/C++/Python.

## Сквозные задачи

- Версионирование (TH4-версия ↔ версия API ↔ версия аддона).
- Тесты протокола (запись/воспроизведение потока кадров — «реплей мира»).
- Документация по мере движения (обновлять эти файлы).
