# 07. Риски, ограничения, юридические вопросы

## Юридические / лицензионные

- **Исходники TH4** открыты с явного разрешения автора: «делай что хочешь, но назови
  производную работу иначе (не используй имя **The Hell**) и сохрани README». → Мы **не**
  имеем права называть наш проект/мод «The Hell»; нужно своё имя.
- **Ассеты Diablo 1** (`DIABDAT.MPQ`) — собственность Blizzard, продаётся (GOG).
  **Нельзя** распространять их. Ассеты самого TH (`TH4data.mor`) — работа команды TH.
- **Вывод для публикации:** публичный релиз не должен содержать чужих ассетов.
  Правильный путь — читать ассеты **из установки пользователя во время работы**
  (не бандлить), а наш код/свои текстуры — свободно.
- **Garry's Mod Workshop:** публиковать аддон можно, если он не несёт чужого
  лицензированного контента. Для личного использования ограничений меньше, но лучше сразу
  проектировать «без чужих ассетов в поставке».

## Технические

| Риск | Суть | Смягчение |
|---|---|---|
| Сборка TH4 из исходников | Форк может не собираться/не совпадать с играбельной версией | Спайк на раннем этапе; fallback на чтение памяти |
| Хрупкость смещений (вариант B) | Адреса меняются между сборками | Приоритет варианту A; версия exe-хеша |
| Задержка IPC | Файловый IPC на 60 Гц тормозит | Бинарный модуль / pipe / shared memory |
| Бинарные модули GMod | ABI/разрядность (x64 для `gmod_win64.exe`) | Проверить ABI; начать с файлового MVP |
| Рассинхрон представления и логики | GMod «додумывает» → расхождение | TH4 — единственный источник правды; интерполяция только для визуала |
| Производительность рендера | 112×112 клеток + сущности = много объектов | Отсечение по видимости, `mesh`-батчинг, LOD |
| Смена уровня/сохранения | Полная перегенерация сцены | Событие «level_changed» с полной пересылкой уровня |
| Идентификаторы сущностей | Переиспользование слотов в массивах | Эпохи/генерации id |
| Юнит-масштаб и коллизии | Тайловая логика ≠ физика Source | Своя логика движения по сетке в Lua |
| Версии игры | TH4 «почти завершён», но обновляется | Версионировать API и целевую версию TH4 |

## Продуктовые/процессные

- Проект большой. Без чёткого MVP рискуем «утонуть» в 3D-ассетах.
- Нужна измеримая вертикаль: сначала **тонкий сквозной поток** (данные из TH4 → 3D-вид),
  потом наращивание качества.
- Поддержка форка TH4 при обновлениях мода — постоянная задача (если идём через исходники).

## Что НЕ делаем (и почему)

- Не переносим игровую логику в GMod (дублирование и рассинхрон).
- Не используем синтетический ввод (`SendInput`) как основной механизм.
- Не публикуем чужие ассеты.
- Не называем проект «The Hell…».
