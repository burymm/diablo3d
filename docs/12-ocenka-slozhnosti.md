# 12. Оценка сложности (черновик)

Оценки — для **одного человека с ИИ-помощью**, в «фокусных днях». Это диапазоны, а не
обещания: главная неопределённость — поиск адресов под конкретную сборку 0.772 и задержка
управления.

Шкала сложности: 🟢 низкая · 🟡 средняя · 🔴 высокая.

---

## Часть 1. Прототип «есть контакт» (проверка гипотезы, только чтение)

| Компонент | Сложность | Оценка | Комментарий |
|---|---|---|---|
| Найти процесс `TH4.exe`, открыть, читать/писать память | 🟢 | 2–4 ч | Стандартные WinAPI (`OpenProcess`, `ReadProcessMemory`) |
| Найти базовый адрес модуля | 🟢 | 1–2 ч | Toolhelp32 / `EnumProcessModules` |
| **Инициализация:** найти адрес героя (якорь) | 🟡🔴 | 0.5–2 дня | По имени героя → pointer-scan в Cheat Engine; главный риск — динамические указатели |
| Читать поля `Player` (Row/Col, HP, мана, dlvl) | 🟢 | 2–4 ч | Раскладка полей уже известна из `structs.h` |
| Писать `snapshot.json` (атомарно) | 🟢 | 1–2 ч | temp → rename |
| GMod-прототип: прочитать файл и показать значения | 🟢 | 2–4 ч | `file.Read` + `util.JSONToTable` |

**Итого прототип (чтение):** ≈ **2–4 дня**, из которых львиная доля — поиск стабильного
указателя на героя.

**Расширение чтения до всего мира** (карта `PlayerMap`/`TileMap`, монстры, предметы,
объекты, снаряды): 🟡🔴 **+1–2 недели** (много отдельных адресов и структур, но всё по
исходникам).

## Часть 2. Подключение к Garry's Mod (способы и их сложность)

| Способ | Сложность | Задержка | Плюсы | Минусы |
|---|---|---|---|---|
| **A. Файл-JSON** в `garrysmod/data/` | 🟢 | высокая (диск, ~10–60 Гц) | Ноль нативного кода, мгновенный старт | Дисковый I/O, не для 60 Гц, «на один компьютер» |
| **B. Нативный модуль GMod** (`gmcl_*.dll`) с сокетом/shared memory | 🔴 | очень низкая | Продакшен, честные 60 Гц | Сборка под ABI GMod + разрядность (x64), LuaJIT; отладка неудобная |
| **C. Локальный HTTP + `http.Fetch`** | 🟡 | средняя | Универсально (любой движок) | Асинхронно, лимиты частоты, тоже «на один компьютер» |
| **D. SQLite через `sql`** | 🟡 | средняя | Без нативного кода | Хак, нагрузка на диск, плохо масштабируется |

**Рекомендация:** прототип — **A** (файл). Если на этапе управления упрёмся в задержку —
переходим на **B** (нативный модуль), либо на named pipe/shared memory.

## Часть 3. Полная цель «играбельно в 3D (FPS)»

| Этап | Сложность | Оценка | Что внутри |
|---|---|---|---|
| Импорт геометрии уровня в 3D (пол/стены/двери) | 🔴 | 2–4 нед | Классификация клеток, генерация мешей, материалы, отсечение |
| Сущности в 3D (герой/монстры/предметы) | 🟡 | 1–2 нед | Билборды, направление (8 dir), анимации, интерполяция |
| Обратный канал управления | 🟡🔴 | 3–7 дней | Клик-эмуляция (нужна формула проекции) или запись цели в память |
| Борьба с задержкой (предсказание в GMod) | 🔴 | 1–2 нед | Клиентское предсказание + реконсиляция с TH4 |
| HUD/инвентарь/скиллы (derma/VGUI) | 🟡 | 1–2 нед | События (урон/смерть/подбор), панели |
| FPS-камера, коллизии камеры, viewmodel | 🟡🔴 | 2–4 нед | Самая «дорогая» часть визуала |
| Оптимизация рендера (112×112 + сущности) | 🟡🔴 | 1–2 нед | Батчинг `mesh`, LOD, видимость |

**Итого до «играбельного 3D-FPS»:** грубо **2–4 месяца** сфокусированной работы.
До «просто посмотреть на уровень в 3D» (вьюер сверху) — **2–4 недели** (после прототипа).

## Часть 4. Это отдельный мод?

**Да, и даже два отдельных куска.**

1. **GMod-сторона** — это **отдельный мод GMod**: аддон в
   `garrysmod/addons/d1source/` (или гейммод в `garrysmod/gamemodes/`). Он самодостаточен:
   свои Lua-файлы, своя конфигурация. Ставится/удаляется независимо.
2. **Diablo-сторона** — отдельный «reader» (утилита) и, позже, патч/сборка `TH4.exe`.
   Живёт в нашем репозитории, но в игру не «встраивается».

Они общаются через транспорт (файл/сокет), поэтому **не обязаны** лежать в одной папке и
могут развиваться раздельно. Именно это делает «мост» универсальным: GMod-мод — лишь первый
потребитель.

### Предлагаемая раскладка (когда дойдём до кода)

```
e:\games\diablo-1-source\
├─ bridge/            ← наша «прослойка» (reader → snapshot/сокет), инструмент
│  └─ (позже) th4-export/   ← патч/сборка TH4 с экспортом
├─ gmod-mod/          ← отдельный GMod-аддон (его потом копируем в garrysmod/addons/)
│  └─ lua/...
├─ docs/              ← текущая база знаний
└─ vendor/the-hell-4-src/
```

## Что определяет срок (главные неизвестные)

1. **Стабильность указателя на игровой мир в 0.772.** Если находится «статическая» база —
   прототип быстрый. Если всё динамическое (аллокации) — дольше и хрупче.
2. **Задержка цикла управления.** Может «убить» FPS-ощущение и потребовать нативного
   модуля и предсказания.
3. **Арт 2D→3D.** Чем «аутентичнее» хотим (вариант C из `06`), тем дороже.
4. **Нативный модуль GMod.** Если он понадобится — это отдельный заметный кусок (сборка,
   ABI, x64).

## Вывод

- **Проверка гипотезы (читать данные, возможно кликать) — реально 2–5 дней.**
- **«Подключить к GMod» по-простому (файл) — часы.**
- **«Играбельный 3D-FPS» — это уже месяцы и отдельный GMod-мод.**
- Значит: сначала дешёвый сквозной прототип, затем решаем по задержке и арту.
