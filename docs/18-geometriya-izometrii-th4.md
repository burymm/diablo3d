# 18. Геометрия изометрии TH4 — точная математика

Выведено расчётом и проверено на всех 8 направлениях TH4. Это фундамент
и для 3D-сцены, и для 2D-изометрии, и для сопоставления с оригиналом.

---

## 1. Как TH4 рисует карту

TH4 — 2D-изометрия, экранные координаты клетки:

```
px = (dRow - dCol) * 64      (вправо)
py = (dRow + dCol) * 32      (вниз)
```

где `dRow/dCol` — сдвиг относительно клетки героя.

Отсюда **направления TH4** (`changeRow/changeCol` из `Player.cpp:6051-6058`):

| PCMD | Имя | dRow | dCol | px | py |
|------|-----|------|------|----|----|
| 1 | up-right | 0 | −1 | +64 | −32 |
| 2 | up-left | −1 | 0 | −64 | −32 |
| 3 | down-right | +1 | 0 | +64 | +32 |
| 4 | down-left | 0 | +1 | −64 | +32 |
| 5 | up | −1 | −1 | 0 | −64 |
| 6 | right | +1 | −1 | +128 | 0 |
| 7 | down | +1 | +1 | 0 | +64 |
| 8 | left | −1 | +1 | −128 | 0 |

## 2. Точный 3D-эквивалент (3D-сцена GMod)

Мир GMod — **Z-up**: X=восток, Y=север, Z=вверх. Клетка (Row, Col):

```
X = Col * k
Y = Row * k
Z = 0
```

Камера:

```
yaw   = 225°
pitch = +30°      (положительный pitch = смотрим вниз)
```

**Проверка** (ортографическая проекция камеры GMod):
`right = (sin yaw, −cos yaw, 0)`, `up = (cos yaw·sin pitch, sin yaw·sin pitch, cos pitch)`,
`screen_x = P·right`, `screen_y_down = −(P·up)`, масштаб `k = 90.51/CELL`:

| PCMD | 3D → экран | TH4 → экран | |
|------|------------|-------------|---|
| 5 up | (0, −64) | (0, −64) | ✅ |
| 1 up-right | (64, −32) | (64, −32) | ✅ |
| 2 up-left | (−64, −32) | (−64, −32) | ✅ |
| 6 right | (128, 0) | (128, 0) | ✅ |
| 7 down | (0, 64) | (0, 64) | ✅ |
| 3 down-right | (64, 32) | (64, 32) | ✅ |
| 4 down-left | (−64, 32) | (−64, 32) | ✅ |
| 8 left | (−128, 0) | (−128, 0) | ✅ |

**Расхождение — 0 px.** То есть 3D-камера в GMod с этими параметрами даёт
**ровно** изометрию TH4.

### Следствия

* **W (вперёд)** при `yaw=225` → `PCMD_5` (вверх по экрану TH4) ✅
* **D (вправо)** → `PCMD_6` (вправо по экрану TH4) ✅
* Направления в сетке ложатся ровно через 45° → «ближайшее направление»
  ищется сравнением yaw без приближений.
* `k = 90.51 / CELL` — так, чтобы шаг клетки на экране был 64 px.

### Важно: знак «вправо»

Работает **только** в правой системе GMod (Z-up, `right = (sin yaw, −cos yaw)`).
Если считать `right = (−sin yaw, cos yaw)` (как в Y-up Source), «вправо»
перевернётся: D уйдёт влево.

## 3. Та же формула для 2D-изометрии (без 3D)

Если рисовать изометрию полигонами/текстурами прямо на экране, нужна та же
ортографическая проекция:

```lua
right = ( sin yaw, -cos yaw )
up    = ( cos yaw*sin pitch, sin yaw*sin pitch )

screen_x      = ( (P - hero) · right ) * k
screen_y_down = -( (P - hero) · up    ) * k      -- k = 90.51/CELL
```

При `yaw=225`, `pitch=30` это даёт те же `(dRow−dCol)·64` и `(dRow+dCol)·32`.

### Углы клетки в экранных координатах

Для клетки (row, col) с мировыми углами A/B/C/D:

```
A = (col,   row  )  — верхняя вершина ромба
B = (col+1, row  )  — левая
C = (col,   row+1)  — правая
D = (col+1, row+1)  — нижняя
```

Видимые грани стены (при камере со стороны `+Col`/`+Row`):
* грань `+Col` — ребро **B→D**;
* грань `+Row` — ребро **C→D**;
* сверху — ромб, сдвинутый вверх на высоту стены.

## 4. Что из этого используется в коде

| Файл | Использование |
|------|--------------|
| `bridge/gmod/d1control.lua` | `TH4_BASE_YAW = 225`, `TH4_BASE_PITCH = 30`; `DIR_VECTORS` в координатах `(X = dCol, Y = dRow)`; базис камеры через `Angle(0, camYaw, 0):Forward()/Right()` (только `x`/`y` — **Z-up!**) |

| `bridge/gmod/d1iso.lua` | ортографическая проекция (раздел 3), сортировка по глубине (алгоритм художника) |

## 5. Проверка на реальных данных

`d1scene_info` печатает и 3D-координаты героя, и TH4-экранные:

```
герой R65 C61 -> 3D (3904, 4160), TH4-экран (256, 4032)
```

`TH4-экран` считается по формуле TH4: `(hr-hc)*64`, `(hr+hc)*32` — это
**эталон**, с которым сверяется всё остальное.
