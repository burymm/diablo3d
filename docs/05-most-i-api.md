# 05. Мост и API: модель данных, транспорт, команды

Цель — **универсальный, версионированный API** к состоянию Diablo 1 (TH4), не привязанный
к GMod. GMod — первый потребитель, но не единственный.

## Модель данных (что передаём)

### Уровень сессии/мира (меняется редко)
```jsonc
{
  "proto": "d1api/0.1",
  "tick": 123456, "time_ms": 98765,
  "game": { "mod": "TH4", "version": "0.7xx", "mode": "SP|MP", "difficulty": 0,
            "gamemode": "NORMAL|HARDCORE|IRONMAN|NIGHTMARE", "dlvl": 5 },
  "map":  { "w": 112, "h": 112, "seed": 12345,
            "iso": { "tile_step_x": 32, "tile_step_y": 16 } }
}
```

### Статическая геометрия уровня (по смене уровня)
- Тайлы: для каждой клетки `(x,y)` — тип и слои (`TileColumn`): `floor|wall|door|arch|
  stairs|water|...`, плюс флаги `blocks_walk`, `blocks_sight`, `blocks_missile`, `is_wall`.
- Освещение: статическое (`StaticLightMap`) и динамическое (`LightMap`).
- Это то, из чего потребитель строит 3D-геометрию.

### Сущности (каждый тик)
```jsonc
{
  "players":  [{ "id": 0, "class": "TEMPLAR", "row": 40, "col": 42, "x": 12.5, "y": 3.0,
                 "dir": 3, "anim": "walk", "frame": 2, "hp": 120, "hp_max": 150,
                 "mp": 40, "gold": 1234, "level": 7, "xp": 100, "flags": ["running"] }],
  "monsters": [{ "id": 17, "type": "SKELETON", "boss": null, "row": 50, "col": 51,
                 "dir": 5, "anim": "attack", "frame": 1, "hp": 30, "hp_max": 40,
                 "target": 0, "ai": 3 }],
  "objects":  [{ "id": 3, "type": "DOOR|BARREL|SHRINE|...", "row": .., "col": .., "state": .. }],
  "items":    [{ "id": 9, "row": .., "col": .., "base": "SWORD", "affixes": [...], "unique": null }],
  "missiles": [{ "id": 5, "type": "FIREBOLT", "x": .., "y": .., "dir": .., "owner": 0 }]
}
```

### События/дельта (для UI, звука, эффектов)
- Урон/смерть, подбор предмета, каст, открытие двери, смена уровня, всплывающий текст,
  запрос звука. Событие: `{ "t": "damage", "target": 17, "amount": 12, "type": "fire" }`.

### Команды (ввод игрока обратно в TH4)
- `move_to(row,col)` / `move_dir(dir)`
- `attack(target_id)` / `attack_ground(row,col)`
- `cast(spell, target_id|row,col)` / `set_ready_spell(spell)`
- `use_object(id)` / `pickup(item_id)` / `drop(item_id)`
- `use_item(inv_slot)` / `talk(npc_id)` / `enter_level(dlvl)`
- `ui(action, args)` — открыть инвентарь/скиллбук/персонажа и т.п.

Контракт команд: потребитель **не** задаёт состояние напрямую, а выражает намерение; TH4
сам решает, возможно ли действие (это сохраняет «единый источник правды»).

## Транспорт (варианты)

| Вариант | Задержка | Сложность | Когда использовать |
|---|---|---|---|
| Файл-JSON в `garrysmod/data/` | высокая (диск) | низкая | MVP, отладка, прототип |
| Named pipe (Windows) | низкая | средняя | продакшен на одной машине |
| TCP/UDP (localhost) | низкая | средняя | продакшен, кроссплатформенно |
| Shared memory | очень низкая | средняя | максимальная производительность |
| HTTP/WebSocket | средняя | средняя | универсальный API для чужих движков |
| SQLite (через `sql`) | средняя | низкая | хак; избегать |

**Рекомендация:**
- MVP: **файл** (нулевой нативный код, быстро проверяем идею).
- Продакшен: **named pipe или localhost TCP** + бинарный модуль в GMod; плюс опциональный
  **HTTP/WebSocket-шлюз** для «любой игры».

## Формат кадра

- **JSON** — удобно читать/отлаживать, но тяжело для 60 Гц.
- **Бинарный (packed structs)** — быстро, но нужно версионировать.
- Компромисс: **бинарный поток сущностей + JSON-заголовок/события**, либо
  **CBOR/MessagePack**. Решение — за обсуждением (`08`).

## Частота и синхронизация

- TH4 в конфиге по умолчанию `fps 203` (переменная), реально логику можно опрашивать
  с нужной частотой (20–60 Гц).
- На стороне GMod — **интерполяция** между снимками, чтобы движение было плавным.
- Разделять: «статический уровень» (редко) и «дельта сущностей» (часто).

## Идентификаторы и стабильность

- Сущностям нужны **стабильные id** между кадрами (индексы в массивах TH4 подходят, но
  слоты переиспользуются — нужны «generation/epoch» или сравнение по позиции/типу).
- Версионирование протокола обязательно (`proto`), с обратной совместимостью или явным
  отказом.

## Ввод: как отправлять команды в TH4

- **Вариант A (в исходниках):** слой команд, который вызывает те же внутренние функции,
  что и UI/мышь (например, установка `destAction/destParam*` у `Player`, каст через
  существующие обработчики). Максимально надёжно.
- **Вариант B (снаружи):** синтетический ввод (`SendInput`) — хрупко, только как костыль
  для прототипа; НЕ рекомендуется как основа.

## Открытый вопрос: несколько игроков

- Один TH4 = один мир = один игрок «по-настоящему» (в SP) или группа (в MP с turn-based
  сетью). Для «GMod-сервер + много игроков, у каждого свой TH4» архитектура усложняется
  радикально (см. `08`).
